# Working Novelty Boundary

This is a planning document.

It is not a final novelty claim.

## Target contribution intersection

The intended contribution combines:

1. physically meaningful IMU/sensor faults
2. embedded TinyML compute faults
3. combined cross-layer conditions
4. lightweight runtime detection
5. selective recovery/fallback
6. embedded resource and timing evidence

The project should not claim novelty merely from:

- injecting IMU noise
- sensor reliability gating
- uncertainty estimation
- neural-network bit flips
- redundancy
- lightweight CNN deployment
- quantization

## Mandatory novelty re-check

Before manuscript submission:

- repeat literature search
- check late-2026 and 2027 work
- identify nearest competing systems
- compare exact system capabilities
- constrain claims to evaluated evidence
