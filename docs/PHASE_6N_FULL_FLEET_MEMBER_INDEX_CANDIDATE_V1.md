# Phase6N full-fleet canonical member index candidate v1

## Objective

Extend the qualified complete subject-9 canonical member expansion
to all 61 frozen outer subjects and 732 subject-family shards.

This is a metadata-only prospective Phase6N development artifact.
No scientific selection, fault protocol, clean cache, frozen file
or historical numerical evidence is modified.

## Complete pair-member indexing

For each subject, the frozen Phase6K metadata auditor is rerun.
Every retained model-independent pair is ordered through frozen
Phase6J canonical pair sorting.

Every frozen-eligible model variant and seed (42, 123, 2025)
is visited within its canonical member stream.

The stream contains a new SHA-256 digest built from a domain-separated
stream header and ordered, independently derived pair fingerprints.
The stream binds shard, model member, clean-cache identity, producer
SHA-256 and selected frozen pair identities.

Each of the 732 per-shard model-member and temporal workload totals
must match the independently frozen Phase6K numerical evidence.

The subject-9 member counts and cache identities must also reconcile
with the previously qualified complete subject-9 Phase6N report.

This qualifies the complete metadata identity and member ordering
surface, not the actual scientific model-forward execution.

## Phase6G request payload validation

For each of the 61 subjects, one representative selected pair for
each of the 28 frozen compute strata is expanded into every eligible
variant/seed combination.

The resulting Phase6G pre-forward requests are built and validated
with frozen Phase6G functions, including persistence, model route
and temporal overlap contracts.

This is an explicitly sampled Phase6G payload qualification.
It does not claim that all 21,793,038 complete request payloads
have been built or individually validated.

## Computational and scientific boundaries

The frozen Phase6K metadata auditor reads source CSV line counts to
derive trial lengths without parsing raw signal values.

No raw signal samples, label arrays, prediction/probability rows,
checkpoint loads, actual sensor conditioning, compute mutations,
model forwards or CSC output artifacts are produced.

Existing Phase5 clean caches are bound by their qualified identities
and producer hashes; this stage does not rehash their output files.
Phase6L previously qualified those real cache files.

The new Phase6N stream digests have their own serialization and must
never be misrepresented as reconstructed historical Phase6E digests.
The original Phase6E digest serializer remains unresolved.
